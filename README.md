# Воркшоп: Оркестрация Python от Cron до Airflow

реализуем один и тот же ML-пайплайн тремя способами:
**Crontab → APScheduler/Dramatiq → Airflow**

## Quickstart

### 1. Клонирование и установка

```bash
# клонируем, переходим в папку с репозиторием
# git clone ...
# cd workshop-repo
uv sync
cp .env.example .env
```

### 2. Настройка окружения

Отредактируйте `.env` и укажите ваше имя:
```bash
PARTICIPANT_NAME=ваше_имя
API_BASE_URL=http://foo.bar.baz.qux:8000
```

### 3. Проверка подключения к API

```bash
python scripts/test_api_connection.py
```

Должны увидеть успешные ответы от всех трёх эндпоинтов.

## Структура воркшопа

### Фаза 1: Crontab (45 мин)
**Директория:** `phase1_crontab/`

Простой Python-скрипт, запускаемый по расписанию cron.

Почувствуйте боль 🤘🏻:
- Нет логики повторных попыток
- Сложно отлаживать
- Нет управления зависимостями
- Обработка ошибок везде вручную

**Цель:** Заставить пайплайн работать, затем сломать его и посмотреть, что произойдет.

### Фаза 2: APScheduler + Dramatiq (60 мин)
**Директория:** `phase2_dramatiq/`

Оркестрация с очередями задач. На что посмотреть:
- Повторные попытки задач с экспоненциальной задержкой
- Зависимости и цепочки задач
- Улучшенную наблюдаемость
- Пулы воркеров

**Цель:** Переписать/адаптировать Фазу 1 в задачи с правильной логикой.

### Фаза 3: Airflow (50 мин)
**Директория:** `phase3_airflow/`

Workflow-движок "энтерпрайз"-уровня. На что смотреть:
- Визуализацию DAG
- UI для мониторинга
- XCom для передачи данных
- Мониторинг SLA
- Backfilling

**Цель:** Реализовать тот же пайплайн как Airflow DAG.

## Требования

- Python 3.10+
- uv (для управления зависимостями): `pip install uv`
- Docker & docker-compose (для Фазы 2 и 3)
- Текстовый редактор
- Доступ к API инструктора

## Пайплайн

Каждая фаза реализует один и тот же пайплайн fraud detection:

```
┌─────────────────────────────────────────────────────────┐
│ 1. Получить последние транзакции (за 15 мин)            │
│ 2. Обогатить данными пользователей                      │
│ 3. Обогатить риск-скорами мерчантов (нестабильный API!) │
│ 4. Создать фичи для модели                              │
│ 5. Запустить модель детекции мошенничества              │
│ 6. Сохранить предсказания                               │
│ 7. Отправить метрики в Prometheus                       │
└─────────────────────────────────────────────────────────┘
```

⚠️ API риск-скоров мерчантов **специально нестабилен** - нужно обрабатывать таймауты и ошибки!

## Мониторинг

Пайплайны отправляют метрики в Prometheus Pushgateway. Смотрите их в Grafana:
- Процент обнаруженного мошенничества
- Обработанные транзакции
- Длительность пайплайна
- Количество ошибок API

Спросите у инструктора, куда это отправлять.
