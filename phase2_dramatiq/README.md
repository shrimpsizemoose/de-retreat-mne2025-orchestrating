# Фаза 2: APScheduler + Dramatiq

Переписываем монолитный скрипт в задачи с очередью:
- Разбиение пайплайна на отдельные задачи
- Автоматические повторные попытки с экспоненциальной задержкой
- Зависимости между задачами 🔥
- Параллельное выполнение через воркеров

## Задача

1. Завершите реализацию задач в `tasks.py`
2. Настройте APScheduler в `scheduler.py`
3. Запустите воркеры и планировщик
4. Наблюдайте за автоматическими повторами при сбоях

## Архитектура


## Установка

### 1. Запустите Redis в докере

```bash
cd phase2_dramatiq
docker-compose up -d
```

### 2. Запустите Dramatiq воркеров

```bash
# В отдельном терминале
uv run dramatiq tasks --processes 2 --threads 4
```

### 3. Запустите планировщик

```bash
# В другом терминале
uv run python scheduler.py
```

## Ключевые концепции

### Retry Logic

Dramatiq автоматически повторяет неудавшиеся задачи:

```python
@dramatiq.actor(max_retries=5, min_backoff=1000, max_backoff=30000)
def fetch_data():
    # Автоматический retry с экспоненциальной задержкой
    pass
```

### Task Chaining

Задачи могут передавать данные друг другу:

```python
# Отправить задачу и получить результат
task1.send().get_result(block=True, timeout=60000)
```

### Error Handling

Даже с retries, некоторые задачи могут зафейлиться. Обрабатывайте это:

```python
try:
    result = task.send().get_result(timeout=60000)
except Exception as e:
    logger.error(f"Task failed after retries: {e}")
    # Используйте дефолтные значения
```

## Преимущества в сравении Crontab

✅ **Автоматические retry** - не нужно писать try/except везде
✅ **Параллелизм** - воркеры могут обрабатывать задачи параллельно
✅ **Лучшая наблюдаемость** - логи задач, метрики выполнения
✅ **Изоляция сбоев** - одна задача не роняет весь пайплайн
✅ **Гибкое расписание** - APScheduler проще настраивать чем cron

## (тизер) Недостатки vs Airflow

❌ **Нет UI** - всё через логи и метрики
❌ **Нет визуализации DAG** - зависимости в коде
❌ **Нет backfilling** - нельзя легко перезапустить прошлые периоды
❌ **Ручное управление состоянием** - нужно самим хранить результаты
